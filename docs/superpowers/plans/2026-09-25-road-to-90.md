# Road to 90% Readiness — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take Lead Engine from its measured baseline (~53%) to ≥90% launch readiness by closing the remaining verified gaps in five ordered waves.

**Architecture:** Waves are sequenced by dependency and file ownership: land in-flight agent work first (W4a), then database-layer tenant isolation (W4b), then privacy mechanics that ride on the worker tick (W4c), then production proof (W4d), then verification debt (W4e), then hygiene (W4f). Each wave ends with the full local gate green and an explicit readiness delta against the model below.

**Tech Stack:** FastAPI + psycopg/psycopg_pool on Supabase Postgres (`engine` schema, RLS, transaction-local org GUC), SQLite for tests, React 19 + Vite + vitest, Vercel serverless + cron, GitHub Actions CI.

**Spec:** `docs/gap-register-2026-09-25.md` (evidence-backed register; this plan argues from it) + the readiness model defined here.

## Global Constraints

- NEVER `git add`/`commit` without the user's explicit instruction; pushes to `main` are authorized wave-by-wave, and only after the **complete local suite** passes (`pytest tests/ -q --cov=lead_engine --cov-fail-under=60` + `ruff check lead_engine/ tests/ api/ --select E9,F63,F7,F82` + `tsc --noEmit` + `vitest run` + `pnpm build`).
- Production Postgres DDL/DML only via the Supabase **Management API** (`sbp_` token, `POST /v1/projects/{ref}/database/query`), and only after the owner explicitly authorizes that specific change. Never retry blocked direct-psycopg DDL. No synthetic rows may remain in production after any probe.
- Never write token literals into tracked files — redact to prefix/suffix form. The working tree may contain the user's concurrent edits: re-run typecheck/tests before and after touching shared files.
- Every subagent claim is unverified until reproduced by execution (register "Disproven claims" table exists because this failed before).
- Agent file ownership while waves A–D are in flight: `api/app.py` → agent A; `lead_engine/activity/*` → agent B; `web/**` → agent C; nothing → agent D (read-only). Do not edit owned files until the agent has reported and its work is verified.

Five dimensions × 20 points = 100. Baseline is measured, not guessed.

| Dimension | What it covers | Baseline |
|---|---|---|
| الوظيفة (Works) | Core E2E in prod, durable execution, latency, audit read path | **16/20** |
| الأمان (Safe) | RLS completeness, least-privilege role, secrets/scanning, backup, PII | **9/20** |
| الشفافية (Honest) | Failure surfaces, frontend defects, zombie state, DATA-01 | **14/20** |
| الإثبات (Verified) | Prod E2E proof, page tests, statement guard, a11y verification | **9/20** |
| الاستدامة (Sustainable) | Ruff debt, env/domain hygiene, docs/runbooks | **5/20** |

## Wave W4b — Tenant isolation hardening (+6)

Gap: not every `engine` table has RLS, and role `lead_engine` holds blanket UPDATE/DELETE/TRUNCATE on all 27 tables.

### Task 6: Introspect and generate the RLS hardening migration

**Files:**
- Create: `supabase/migrations/20260926_0001_rls_hardening.sql` (unapplied until authorized)
- Test: `tests/test_schema_parity.py` (extend)

**Interfaces:**
- Consumes: `SUPABASE_DB_URL` DSN; Management API apply path from memory `lead-engine-dev-and-secrets`
- Produces: every org-scoped table in `engine` has `ENABLE ROW LEVEL SECURITY` + a `tenant_isolation` policy identical in shape to the existing one: `organization_id = COALESCE(current_setting('app.current_org', true), '') OR organization_id IS NULL`

- [ ] Write and run the read-only introspection script (scratch/, `python -u`):

```python
import os, sys
sys.path.insert(0, ".")
from lead_engine.config import load_env
load_env()
import psycopg
from psycopg.rows import dict_row
with psycopg.connect(os.environ["SUPABASE_DB_URL"], row_factory=dict_row,
                     options="-c search_path=engine", autocommit=True) as conn:
    cur = conn.cursor()
    cur.execute("""
        SELECT c.relname AS table,
               c.relrowsecurity AS rls_on,
               coalesce(p.polname, '-') AS policy
        FROM pg_class c
        JOIN pg_namespace n ON n.oid = c.relnamespace
        LEFT JOIN pg_policy p ON p.polrelid = c.oid
        WHERE n.nspname = 'engine' AND c.relkind = 'r'
        ORDER BY c.relname
    """)
    for r in cur.fetchall():
        print(r["table"], "RLS:", r["rls_on"], "policy:", r["policy"])
    cur.execute("""
        SELECT table_name, privilege_type FROM information_schema.role_table_grants
        WHERE grantee = 'lead_engine' AND table_schema = 'engine'
          AND privilege_type IN ('TRUNCATE', 'DELETE', 'REFERENCES', 'TRIGGER')
        ORDER BY table_name, privilege_type
    """)
    for r in cur.fetchall():
        print("grant:", r["table_name"], r["privilege_type"])
```

- [ ] Every table printed with `RLS: off` gets a policy stanza in the migration:

```sql
ALTER TABLE engine.<table> ENABLE ROW LEVEL SECURITY;
ALTER TABLE engine.<table> FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS tenant_isolation ON engine.<table>;
CREATE POLICY tenant_isolation ON engine.<table>
  USING (organization_id = COALESCE(current_setting('app.current_org', true), '')
         OR organization_id IS NULL)
  WITH CHECK (organization_id = COALESCE(current_setting('app.current_org', true), '')
              OR organization_id IS NULL);
```

  Exception: tables the app must read cross-tenant (if introspection shows any, e.g. `providers`, `icp_versions` shared config) get the read-only variant `FOR SELECT USING (true)` with a comment naming the table — decided per table from the introspection output, never bulk.
- [ ] Least-privilege stanza (unconditional — the engine code never issues TRUNCATE; confirmed by `grep -ri "truncate" lead_engine/` returning zero engine statements):

```sql
REVOKE TRUNCATE ON ALL TABLES IN SCHEMA engine FROM lead_engine;
```

- [ ] `FORCE ROW LEVEL SECURITY` must be applied only to tables the app writes through the GUC path — verify against the `_bind_org` flow before including FORCE for any table the bootstrap writes with `organization_id IS NULL` rows (NULL rows stay visible under the policy, so FORCE is safe; keep FORCE only where introspection shows org data is always set, and comment each).
- [ ] Extend `tests/test_schema_parity.py` with a static guard: parse every `supabase/migrations/*.sql`, extract tables receiving `ENABLE ROW LEVEL SECURITY`, and assert the set covers every table named in `db_pg.ORG_TABLES` plus `audit_logs`. Run: `pytest tests/test_schema_parity.py -q` — expect green after the migration file exists.
- [ ] Present the migration to the owner; apply via Management API only on explicit authorization; verify by re-running the introspection script (expect `RLS: on` everywhere + zero TRUNCATE grants); smoke the dashboard (org-scoped pages must still return data).
